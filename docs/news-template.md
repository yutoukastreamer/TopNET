# Новостной блок — шаблон и требования к изображениям

Документ для разработчика админ-панели. Описывает **один** стандартный шаблон
новости, который используется в двух местах:

| Слот | Где | Класс рамки | Вариант картинки |
|---|---|---|---|
| **card** | блок «Последние новости» на главной (`index.html`) | `.news-card__media` | вертикальный, 3:4 |
| **cover** | лента новостей (`news.html`) | `.tl-card__media` | горизонтальный |

Внутри обеих рамок лежит **одинаковый** медиа-компонент `.news-media__img`
(стили — `css/style.css`). Отличаются только набор файлов и атрибут `sizes`.

**Формат сайта — WebP.** Копии на сервере лежат только в нём. JPEG-дубль
опционален: шаблон умеет его отдавать, но по умолчанию не используется (§1.2).

---

## 1. Шаблон медиа-блока

### 1.1. Основной вариант — только WebP

Так сейчас в вёрстке. `<picture>` не нужен: у одного формата нечего выбирать.

```html
<img
  class="news-media__img"
  src="assets/images/news/{slug}/{variant}-{maxW}.webp"
  srcset="assets/images/news/{slug}/{variant}-480.webp 480w,
          assets/images/news/{slug}/{variant}-840.webp 840w"
  sizes="{SIZES}"
  width="{maxW}" height="{maxH}"
  alt="{ALT}"
  loading="lazy" decoding="async">
```

Поля админки: `{slug}`, `{variant}`, `{SIZES}`, `{ALT}`, список ширин и
`width`/`height` самой крупной копии.

WebP понимают все актуальные браузеры (Chrome 32+, Firefox 65+, Safari 14+,
Edge 18+) — около 97 % трафика. Кому нужен хвост старых браузеров, включает
вариант 1.2.

### 1.2. Вариант с JPEG-дублем

Если для новости загружен ещё и JPEG, шаблон оборачивается в `<picture>`.
Классы и стили те же, `.news-media` добавляется на `<picture>`:

```html
<picture class="news-media">
  <source
    type="image/webp"
    srcset="assets/images/news/{slug}/{variant}-480.webp 480w,
            assets/images/news/{slug}/{variant}-840.webp 840w"
    sizes="{SIZES}">
  <img
    class="news-media__img"
    src="assets/images/news/{slug}/{variant}-840.jpg"
    srcset="assets/images/news/{slug}/{variant}-480.jpg 480w,
            assets/images/news/{slug}/{variant}-840.jpg 840w"
    sizes="{SIZES}"
    width="840" height="1120"
    alt="{ALT}"
    loading="lazy" decoding="async">
</picture>
```

> **Важно.** В этом варианте `<img src>` и его `srcset` — **всегда JPEG,
> никогда WebP.** `<picture>` откатывается на `<img>`, только если браузер не
> понимает `type="image/webp"`. **На 404 отката нет** — если WebP-файла
> физически нет, пользователь увидит битую картинку. Отсюда: WebP и JPEG в
> этом режиме генерируются строго парой. Нет JPEG — используем вариант 1.1
> без `<picture>` вовсе.

### 1.3. Общие правила

1. Выводить только реально существующие ширины. Если копия одна — `srcset` и `sizes` можно не выводить.
2. `loading="lazy" decoding="async"` — на всех новостных картинках: оба блока лежат ниже первого экрана.
3. `width`/`height` — от самой крупной копии. Вёрстку они не задают (рамку задаёт CSS), но помогают браузеру зарезервировать пропорции.
4. `alt` — отдельное поле в админке. Для декоративных картинок `alt=""`: так сейчас в ленте, где рядом стоит заголовок и дублировать его не нужно.

### 1.4. Точка фокуса кропа

Рамки кропают картинку через `object-fit: cover`, по умолчанию по центру. Если
важный объект смещён, админка задаёт точку инлайном — значение как у
`object-position`:

```html
<img class="news-media__img" style="--news-media-pos: 50% 30%" …>
```

В варианте 1.2 то же самое ставится на `<picture>` — переменная наследуется.

## 2. Слот **card** — карточка на главной

Рамка жёстко `aspect-ratio: 3 / 4`, так что кроп предсказуем: что залили, то и видно.

Замеренная ширина слота (CSS-пиксели):

| Ширина экрана | Ширина слота | Раскладка |
|---|---|---|
| ≥ 1440px | 333px | 3 колонки |
| 1280px | 340px | 3 колонки |
| 1200px | **344px** ← максимум на десктопе | 3 колонки |
| 1024px | 294px | 3 колонки |
| 900px | 258px | 3 колонки |
| 768px | 220px ← минимум | 3 колонки |
| 561–767px | **420px** ← максимум вообще | 1 колонка, `max-width: 420px` |
| 430px | 387px | 1 колонка |
| 360px | 320px | 1 колонка |
| 320px | 280px | 1 колонка |

### Лестница копий (кроп ровно 3:4)

| Файл | Размер | Закрывает |
|---|---|---|
| `card-480` | 480 × 640 | до 480px слота при DPR 1 |
| `card-840` | 840 × 1120 | 420px при DPR 2 |
| `card-1260` | 1260 × 1680 | 420px при DPR 3 |

### `sizes`

```
(min-width: 1200px) 344px, (min-width: 768px) 29vw, (min-width: 480px) 420px, calc(100vw - 40px)
```

## 3. Слот **cover** — карточка в ленте новостей

У рамки **нет** фиксированных пропорций: она меняет и ширину, и высоту при
раскрытии новости. Поэтому копии режутся только по ширине, пропорции мастера
сохраняются, а обрезает CSS.

| Ширина экрана | Свёрнуто | Раскрыто |
|---|---|---|
| ≥ 1440px | 232 × 168 | 930 × 400 |
| 1280px | 232 × 168 | 953 × 384 |
| 1200px | 232 × 168 | **966 × 360** ← максимум |
| 1024px | 232 × 168 | 821 × 307 |
| 900px | 232 × 168 | 720 × 270 |
| 860px | 684 × 150 | 684 × 258 |
| 768px | 601 × 150 | 601 × 240 |
| 560px | 444 × 132 | 444 × 240 |
| 430px | 327 × 132 | 327 × 240 |
| 320px | 220 × 132 | 220 × 240 |

Пропорции рамки гуляют от **0,92 : 1** (мобильный, раскрыто) до **2,68 : 1**
(десктоп 1200px, раскрыто). **Безопасная зона** для мастера 16:9 — центральные
**~50 % ширины и ~65 % высоты** кадра: только это гарантированно видно во всех
состояниях, остальное обрежется в одном из них. Если важный объект выходит за
эту зону — сдвинуть кроп через `--news-media-pos`.

### Лестница копий (пропорции мастера)

| Файл | Ширина | Закрывает |
|---|---|---|
| `cover-640` | 640px | свёрнутую карточку при DPR 2 и мобильные |
| `cover-1280` | 1280px | раскрытую до 640px слота при DPR 2 |
| `cover-1920` | 1920px | раскрытую 966px при DPR 2 |

### `sizes` — две заготовки

Слот прыгает с 232px на 966px при раскрытии, а `sizes` статичен. Поэтому в
разметке лежат оба значения, а `js/news-page.js` переключает их по клику на
«Читать подробнее»: свёрнутая карточка тянет мелкую копию, раскрытая догружает
крупную из того же `srcset`.

```html
sizes="(min-width: 861px) 232px, (min-width: 561px) calc(100vw - 160px), calc(100vw - 100px)"
data-sizes-closed="(min-width: 861px) 232px, (min-width: 561px) calc(100vw - 160px), calc(100vw - 100px)"
data-sizes-open="(min-width: 861px) 966px, (min-width: 561px) calc(100vw - 160px), calc(100vw - 100px)"
```

В варианте 1.2 оба атрибута ставятся **и на `<source>`, и на `<img>`**. JS
выбирает элементы по самому атрибуту (`[data-sizes-closed]`), поэтому работает
в обоих вариантах разметки.

## 4. Загрузка: форматы и максимальные размеры

### Что принимаем от редактора

| Параметр | Значение |
|---|---|
| Форматы | JPEG, PNG, WebP |
| Максимальный вес файла | **10 МБ** |
| Максимальный размер | **6000 × 6000px** (защита от «архивных бомб»); всё, что больше, — отклонять |
| Минимум для `card` | **1260 × 1680px** — ограничивает высота, а не ширина |
| Минимум для `cover` | 1920px по ширине |
| Рекомендуемый мастер | 2560px по длинной стороне |

EXIF/ICC вырезать, но **до этого** применить `Orientation`, иначе фото с
телефона ляжет на бок.

### Апскейл запрещён

Проверять надо **масштаб вписывания**, а не только ширину. Для кропа в
размер (w × h) из мастера (W × H) требуемый масштаб равен
`max(w/W, h/H)`; если он больше 1 — ступень пропускаем.

Для `card` это почти всегда упирается в **высоту**: у горизонтального мастера
максимальный честный кроп 3:4 равен `min(W, H × 3/4)` по ширине. Пример из
текущего контента — мастер 1968 × 1088 даёт максимум `816 × 1088`, то есть
ступени `card-840` и `card-1260` для него недостижимы.

Если мастер не дотягивает до верхней ступени, но даёт заметно больше следующей
снизу (порог — в 1,25 раза), добавляем ступень по его собственному пределу.
Так появились нестандартные `card-804`, `card-816` и `cover-805`.

### До какого размера кодируем

Лестницы выше — это потолок. Кодировать шире смысла нет, ни один слот больше
не занимает:

* `card` — максимум **1260 × 1680px**
* `cover` — максимум **1920px** по ширине

### Настройки кодировщика

Подобраны на реальных фото сайта: при этих значениях WebP стабильно на
**12–30 % легче** JPEG при неотличимой картинке.

| Формат | Параметры | CLI |
|---|---|---|
| WebP (основной) | quality **76**, effort 6, sharp/smart YUV | `cwebp -q 76 -m 6 -sharp_yuv -metadata none in.png -o out.webp` |
| JPEG (опционально) | quality **82**, progressive, 4:2:0 | `magick in.png -strip -interlace Plane -sampling-factor 4:2:0 -quality 82 out.jpg` |

### Потолок веса готовой копии

Если кодировщик выдал больше — картинку стоит пережать или отклонить.
В скобках — фактический вес на текущем контенте сайта.

| Копия | WebP | JPEG (если включён) |
|---|---|---|
| `card-480` | ≤ 80 КБ (14–65) | ≤ 90 КБ |
| `card-840` | ≤ 180 КБ (28–149) | ≤ 220 КБ |
| `card-1260` | ≤ 270 КБ | ≤ 380 КБ |
| `cover-640` | ≤ 110 КБ (12–92) | ≤ 120 КБ |
| `cover-1280` | ≤ 200 КБ (31–168) | ≤ 260 КБ |
| `cover-1920` | ≤ 330 КБ (50–279) | ≤ 450 КБ |

## 5. Имена файлов

```
assets/images/news/{slug}/{variant}-{width}.{ext}
```

* `slug` — идентификатор новости, он же якорь: `news.html#post-{slug}`
* `variant` — `card` или `cover`
* `width` — ширина копии из лестницы
* `ext` — `webp` (основной) или `jpg` (если включён дубль)

Пример — что реально лежит для новости про тарифы:

```
assets/images/news/tariffs/card-480.webp
assets/images/news/tariffs/card-816.webp
assets/images/news/tariffs/cover-640.webp
assets/images/news/tariffs/cover-1280.webp
assets/images/news/tariffs/cover-1920.webp
```

## 6. Новость без картинки

У новости может не быть фото — тогда вместо `<img>` выводится градиентная
заглушка. Стили для обоих блоков в CSS остались:

```html
<!-- главная -->
<div class="news-card__media">
  <span class="news-card__placeholder">Фото проекта</span>
</div>

<!-- лента новостей -->
<div class="tl-card__media tl-card__media--grid" aria-hidden="true">
  <span class="tl-card__media-icon">
    <svg viewBox="0 0 24 24" fill="none">…</svg>
    <span class="tl-card__media-label">Тарифы</span>
  </span>
</div>
```

## 7. Спойлер

Заготовка лежит в `news.html` отдельным блоком после ленты, внутри
`<div class="spoiler-template" data-spoiler-template hidden>`. На странице не
отображается, но стили (`css/news-page.css`, секция «СПОЙЛЕР») рабочие.

```html
<details class="spoiler">
  <summary class="spoiler__head">
    <span class="spoiler__title">Заголовок спойлера</span>
    <span class="spoiler__icon" aria-hidden="true">
      <svg viewBox="0 0 24 24" fill="none"><path d="M6 9l6 6 6-6" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"/></svg>
    </span>
  </summary>
  <div class="spoiler__body">
    <p>Скрытый текст…</p>
  </div>
</details>
```

Нативный `<details>` — JS не нужен, работает с клавиатуры и читалками из
коробки. Уникальные `id`/`name` не требуются, несколько спойлеров в одной
новости допустимы. Поля админки: заголовок и содержимое.

Чтобы включить — убрать `hidden` у обёртки либо перенести `<details>` внутрь
текста новости (`.tl-card__full`).
